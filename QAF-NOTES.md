# Qubators AI Foundry 2.0 — class notes relevant to the build

Kept here so the build follows the program's method and the submission has what the facilitators asked for.

## The complete product map (covered over the program)

1. Plan — users, journeys, requirements
2. Build — AI builder, preview, version history
3. Store and protect — data, files, accounts, permissions
4. Connect services — AI, payments, email
5. Verify and release — testing, hosting, domain
6. Operate — monitoring, recovery, support

## Planning and building — the starting point for every application

- Problem and evidence: who needs this, what do we know about their difficulty
- Journey and interface: the steps the user takes
- Requirements and checks: what must happen, and how we verify it
- Development environment: a place to direct the builder and preview the project
- Coding tool: turn clear instructions into a working application
- Git and a repository: a record of the code and its changes

## The brainstorming method (Session 1, Phase 1)

"I want to build x, y, z (context). Ask me questions, one at a time, to help me create the features for this. Give me your recommendation for each question. Do not include technical specifications."

The brainstorm's outcome is the PRD — the "product bible" — defined as everything that needs to happen before the product is created. Technical specifications come after, at the architecture step.

## PRD structure used in class

Primary purpose (one sentence) → 1. Product vision (the messy current situation, the arrow flow it brings together, the goal) → 2. Target users → journeys → features → requirements → out of scope → success measures.

## What the submission needs

Testing, debugging, version history (GitHub commits per step), and an explanation of the build. Commit after every working step so the history tells the story.
